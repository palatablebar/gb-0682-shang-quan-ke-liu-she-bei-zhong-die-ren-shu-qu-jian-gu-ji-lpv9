# 客流观测与区间

区域人数与两两交集必须是非负整数，单位人或千人。东门、中庭、西门映射为A、B、C。时间先转UTC后形成小时桶；非整点观测向下归入所在UTC小时桶。同一观测按version选择最高版，矛盾同版隔离。v1 以整行判断同版记录是否相同；v2 只比较业务字段（id、bucket、version、kind、left、right、count、unit），备注差异只算重复，不算矛盾。

最多三个区域。两区域无交集观测时联合人数为[max(A,B),A+B]；已知交集I时为A+B-I。三区域需要全部两两交集。三方交集T下界为max(0,AB+AC-A,AB+BC-B,AC+BC-C)，上界为min(AB,AC,BC)。联合人数为A+B+C-AB-AC-BC+T。区间无可行整数时整桶隔离。输出上下界，不估算未经观测的精确人数。日汇总是分桶客次的上下界相加，不宣称是全天独立人数。

## 规则版本与历史数据

规则版本是对采信、取舍、估界与归档口径的完整标识。版本登记在 `app/rulebook.py`，必须同时出现在运行幂等键、批次运行清单、每条观测/估界/隔离记录与封存证据中。缺版本或版本混杂的数据不能合并、不能导出、不能进入日汇总，错误码 `RULE_MIX`。

历史数据采用**并列重述**，不整批迁移：

- 已签发批次的正文、复核版本与指纹只读。规则升级后按原样字节、原规则版本重跑，仍得到原批次与原指纹。
- 需要按新规则观察同一来源时，生成新的并列批次；同源键（输入字节+参数）相同，规则版本不同，`run_id` 不同。并列批次只做对照展示，不互相覆盖。
- 同源同规则重跑命中同一 `run_id`，不新增重复结果；已存在批次只移动“最新”指针，不改正文与复核结论。
- 数据库升级只补旁列（`rule_version`、`source_key`）并逐行回填，不重写正文；迁移前复制 `runs_backup_v2`，任一步失败整体回滚，旧结构与旧证据保持可读。
- 低版本观测被更高版本取代时进入 `superseded` 台账，保留来源行、原值与替代版本，不静默丢弃。

## 通用采信约定

CSV按UTF-8 BOM、UTF-8、GB18030回退，保留逻辑记录结束行号；引号内换行由CSV解析。重复表头单独计数，列数不齐隔离。编码与ID按字符串保形。缺失哨兵为 `-`、`N/A`、`NULL`、`未知` 与空串；不得作为零。数值先NFKC归一、去千分位，再用Decimal。日期采用ISO；时间必须带偏移并转UTC。空文件、全空行、仅表头分别返回EMPTY_FILE、BLANK_FILE、HEADER_ONLY。

重复键为(id,version)，完全相同行去重；同键内容冲突则整组隔离，不取最后一行。行数对账：输入=采纳+隔离+空行+重复表头+完全重复。运行幂等键由输入字节、参数与规则版本计算。

三方交集仅在A、B、C三个区域齐全时适用，类型triple的left必须为ABC，right必须为空。

支持区域固定为A、B、C；其他区域标识拒绝，防止三方ABC记录关联到另一组区域。
